# AI Sana Challenge Hub

Кроссплатформенный сервис для кейса МНВО — AI Sana. Он помогает бизнесу превратить короткое описание проблемы в ясный студенческий проект, а командам — понять задачу и предложить решение.

**Идея позиционирования:** другие платформы уже проводят хакатоны, принимают решения по challenge-задачам и соединяют студентов с бизнесом. Наш узкий фокус — шаг до откликов: улучшить сам бриф, прозрачно показать его готовность и не отбирать у людей решение о сотрудничестве.

## 1. Название проекта

**AI Sana Challenge Hub — Паспорт ясности образовательных задач.**

## 2. Проблема и пользователи

Бизнес часто описывает потребность одной-двумя фразами. Студентам не хватает контекста, доступных данных, ожидаемого результата и критериев успеха, чтобы решить, за что браться. Hub помогает бизнесу уточнить эти пункты и опубликовать понятный бриф. Студенческие команды изучают каталог и отправляют предложения; бизнес вручную выбирает, с кем продолжить работу.

## 3. Что реализовано

- Каталог задач с поиском по тексту и фильтрами по образовательной теме.
- Мастер создания задачи: черновик → уточняющие вопросы → редактируемая карточка → публикация.
- AI-вызов через FastAPI для генерации вопросов и структурирования карточки. Модель не должна придумывать отсутствующие факты; результат проверяет заказчик.
- Демо-режим без API-ключа, чтобы можно было открыть MVP и пройти сценарий.
- Если модель не отвечает или вернула некорректный результат, API переключается на локальный демо-режим и сообщает об этом клиенту.
- «Паспорт ясности»: рейтинг 0–100, вклад каждого поля и список недостающих данных.
- Рейтинг не скрывает задачу и не запрещает командам откликаться.
- Отклик команды: идея, план, срок и необязательная ссылка на прототип.
- Уведомление в приложении после отправки отклика; сообщение также появляется во входящих бизнеса.
- Бизнес вручную принимает или отклоняет предложения. После решения команда получает уведомление внутри приложения.
- Адаптивный Flutter-клиент для Web, Android, iOS, Windows, macOS и Linux; тот же FastAPI API обслуживает браузерную версию.
- Пять демонстрационных образовательных задач и пять примерных откликов. Данные помечены как учебные примеры, а не реальные заявки бизнеса.

## 4. Как работает пользовательский сценарий

1. Представитель бизнеса вводит короткий черновик проблемы.
2. Система задаёт минимум три уточняющих вопроса о том, чего пока не хватает.
3. Ответы становятся черновиком карточки. Заказчик редактирует поля, видит рейтинг готовности и подтверждает публикацию.
4. Студенческая команда находит карточку в каталоге, читает контекст и ограничения, затем отправляет идею и план.
5. FastAPI сохраняет отклик и создаёт сообщение для входящих бизнеса. Команда сразу видит подтверждение отправки.
6. Бизнес просматривает предложения и вручную выбирает или отклоняет команду. Решение вызывает уведомление команде.

Уведомления — **внутри приложения**. Письма, SMS и push-уведомления не подключены.

## 5. Технологии

- **Клиент:** Flutter и Dart; адаптивный Material 3 интерфейс.
- **API:** Python, FastAPI и Pydantic.
- **AI:** OpenAI Responses API или NVIDIA NIM с OpenAI-совместимым API. Ключ хранится только в серверном `.env`.
- **Хранилище:** Supabase Postgres при настройке проекта; SQLite для запуска без внешней базы.
- **Транспорт:** HTTP/JSON между Flutter, браузерным клиентом и FastAPI.

Официальные руководства: [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text), [NVIDIA NIM API](https://docs.nvidia.com/nim/large-language-models/latest/api-reference.html), [Flutter Web](https://docs.flutter.dev/platform-integration/web/building), [FastAPI](https://fastapi.tiangolo.com/tutorial/first-steps/), [Supabase Python](https://supabase.com/docs/reference/python/introduction).

## 6. Архитектура

```text
Flutter: Web / Android / iOS / Windows / macOS / Linux
                         │ HTTP/JSON
                         ▼
                    FastAPI API
             ┌───────────┼───────────┐
             ▼           ▼           ▼
          OpenAI       NVIDIA     Supabase
        Responses      NIM API    Postgres
                                      │
                          если Supabase не настроен
                                      ▼
                                    SQLite
```

Браузерная версия в корневом `index.html` использует тот же API. FastAPI отдаёт её на `http://127.0.0.1:8000/`. Flutter-клиент лежит в `app/`, сервер — в `backend/`, SQL-схема — в `backend/supabase/schema.sql`.

## 7. Установка и запуск

### Запустить Python API и браузерную версию

Нужен Python 3.10 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python3 -m uvicorn backend.main:app --reload
```

Откройте:

- Приложение в браузере: <http://127.0.0.1:8000/>
- Интерактивная документация API: <http://127.0.0.1:8000/docs>

Без ключа модель не вызывается, но интерфейс работает в демо-режиме. Если настроенная модель недоступна, API явно включает локальный резервный режим. Чтобы включить OpenAI, откройте `.env` и укажите свой ключ в `AI_API_KEY`. По умолчанию настроен Responses API и модель `gpt-6-astra`:

```dotenv
AI_PROVIDER=openai
AI_API_KEY=вставьте_ключ_сюда
AI_MODEL=gpt-6-astra
```

Сохраните файл и перезапустите сервер. Если вашей организации недоступна модель по умолчанию, измените `AI_MODEL` на доступную в вашем API-аккаунте.

Для NVIDIA NIM укажите `AI_PROVIDER=nvidia`, свой токен в `AI_API_KEY` и доступное в NVIDIA API Catalog имя модели в `AI_MODEL`. `NVIDIA_BASE_URL` уже содержит стандартный NIM endpoint. Приложение не отправляет секретный ключ из Flutter или браузера.

### Использовать Supabase вместо локальной SQLite

1. Создайте проект Supabase.
2. Откройте **SQL Editor** и выполните скрипт из `backend/supabase/schema.sql`.
3. В корневом `.env` заполните `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` значениями проекта.
4. Перезапустите FastAPI.

Если эти две переменные оставить пустыми, данные сохраняются в `backend/data/hub.sqlite3`. Не вставляйте ключ `service_role` в Flutter, браузер, README или GitHub: он предназначен только для API-сервера.

### Запустить Flutter-приложение

Нужны Flutter SDK и Dart из комплекта Flutter. Для добавления стандартных папок платформ к исходникам проекта:

```bash
cd app
flutter create . --platforms web,android,ios,windows,macos,linux
flutter pub get
flutter run -d chrome --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

Сначала запустите FastAPI из корня репозитория в отдельном терминале. Для запуска на подключённом телефоне используйте адрес компьютера в локальной сети, например:

```bash
flutter run --dart-define=API_BASE_URL=http://192.168.1.25:8000
```

Замените IP на адрес компьютера, где работает FastAPI; телефон и компьютер должны быть в одной сети. В эмуляторе Android приложение по умолчанию использует `10.0.2.2:8000`. Для запуска на Windows/macOS/Linux выберите соответствующее устройство Flutter; desktop runner создаётся командой `flutter create` выше.

## 8. Как проверить MVP

1. Запустите FastAPI и откройте браузерную версию или Flutter-приложение.
2. В каталоге откройте задачу «Раньше замечать, кому из студентов нужна поддержка».
3. Нажмите «Предложить решение», заполните название команды и идею и отправьте отклик.
4. Убедитесь, что показано сообщение об отправке. Откройте «Входящие»: заказчик увидит уведомление с названием команды и задачи.
5. Откройте «Предложения команд», вручную выберите или отклоните команду. Решение появится в статусе отклика.
6. Откройте «Создать задачу», вставьте черновик, получите уточняющие вопросы, заполните ответы и проверьте редактируемый «Паспорт ясности».
7. Опубликуйте карточку и найдите её в каталоге.

В OpenAPI-документации доступны `/api/health`, `/api/tasks`, `/api/ai/refine`, `/api/ai/organize`, `/api/tasks/{id}/responses`, `/api/responses` и `/api/notifications`.

## 9. Данные и интеграции

- При первом локальном запуске создаются пять примерных задач и пять предложений команд.
- AI получает черновик и ответы только при наличии `AI_API_KEY`; FastAPI возвращает ошибки модели без добавления вымышленных данных в карточку.
- SQLite используется для локального старта; Supabase включается серверными переменными окружения и SQL-схемой из репозитория.
- Общий список уведомлений и откликов используется в демонстрационном MVP. Регистрации и разделения пользователей пока нет.
- В каталоге указаны примеры, а не настоящие компании или образовательные заказы.

## 10. Ограничения

- Flutter SDK не включён в репозиторий; команды запуска ниже создают нужные платформенные runner-файлы на компьютере разработчика.
- Для AI нужен действующий API-ключ и модель, доступные конкретному аккаунту. Без ключа интерфейс работает с локальным демо-режимом.
- Supabase требует отдельного проекта и двух серверных настроек. По умолчанию доступна локальная SQLite.
- Нет регистрации, ролей и изоляции бизнес-аккаунтов: приложение предназначено для демонстрации процесса и не должно открываться в публичную сеть без авторизации и серверных правил доступа.
- Сообщения показываются во входящих приложения; email, SMS и push не настроены.
- Рейтинг прозрачно проверяет заполнение полей, но не доказывает качество или реализуемость проекта.
- Источника deployed-версии пока нет; приложение запускается локально по инструкциям выше.
